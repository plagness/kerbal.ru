## Правила работы

1. **Игру запускает пользователь, не ты.** Твоё дело — подготовить скрипт, подключиться
   по telnet и вести полёт. Не запускай KSP сам и не закрывай её.
2. **Не пиши в терминал kOS, пока программа выполняется.** kOS считает любой ввод
   попыткой прерывания и роняет работающий скрипт. Дождись завершения.
3. **Проверяй скрипт до старта.** `RUNPATH("0:/check/libcheck.ks").` на стартовом столе
   ловит ошибки компиляции и опечатки в именах — дешевле, чем потерять ракету.
4. **Имена файлов kOS — только строчными.** На macOS и Linux регистр важен.
5. **Не трогай `saves/`** без явной просьбы. Сейв — единственная невосполнимая вещь.
6. **Не переустанавливай моды руками.** Состав сборки меняет только `install.sh`.

## Как вести полёт

Терминал kOS доступен по telnet, если он включён в настройках kOS (по умолчанию
`127.0.0.1:5410`). Клиент лежит рядом:

```bash
python3 kerbal/tools/kos.py                       # подключиться и показать экран
python3 kerbal/tools/kos.py 'PRINT SHIP:ALTITUDE.'  # выполнить команду и увидеть вывод
python3 kerbal/tools/kos.py --watch 60            # 60 секунд смотреть, не вмешиваясь
```

Файл миссии задаёт только цель — параметры орбиты, остальное считается:

```kos
RUNONCEPATH("0:/lib/mission.ks").
SET s TO m_defaults().
SET s["ap"]  TO 7867078.    // апоцентр, м
SET s["pe"]  TO 3331362.    // перицентр, м
SET s["inc"] TO 20.1.       // наклонение
m_orbit(s).
```

Разбор граблей, на которые мы уже наступали — левосторонняя система координат KSP,
имена встроенных функций, автостейджинг, срыв антенн при передаче науки в атмосфере, —
в `kerbal/wiki/kos-biblioteka.md` и `kos-otladka.md`. Прочитай их **до** первого пуска.

## Нашёл неточность — предложи правку

Проект живёт правками игроков, и большая часть вики написана по разбору реальных
инцидентов в игре. Если ты видишь, что документация расходится с тем, что происходит
на экране, или скрипт работает не так, как описано, — **предложи изменение от имени
пользователя**, а не молча обходи проблему.

Порядок:

1. **Убедись, что это правда.** Приложи доказательство: строку из `KSP.log`, вывод
   терминала kOS, точные цифры орбиты. Догадка без проверки хуже молчания.
2. **Спроси пользователя**, отправлять ли правку. Это публичное действие от его имени —
   без явного согласия не отправляй.
3. **Оформи**:
   - неточность в тексте или готовый фикс → pull request в
     [plagness/kerbal.ru](https://github.com/plagness/kerbal.ru): правь
     `builds/{{WIKI_BUILD_ID}}/wiki/<статья>.md` или файл в `kos/`;
   - воспроизводимый баг или вопрос «как правильно» → issue по шаблону:
     <https://github.com/plagness/kerbal.ru/issues/new/choose>;
   - английская надпись в интерфейсе → issue со скриншотом: каждая такая находка
     становится строчкой в словаре перевода.
4. **Пиши по-русски**, коротко и по делу: что было, что стало, чем подтверждается.
   Правила и стиль — `CONTRIBUTING.md` в репозитории.

Не отправляй правки в чужие моды от имени проекта: мы переводим и документируем,
но чужой код не трогаем.
