# kOS-библиотека сборки «Оператор»

Готовые блоки для автоматизации полётов в Kerbal Space Program через
[kOS](https://github.com/KSP-KOS/KOS). Не «скрипт на один запуск», а набор
модулей: подъём, узлы манёвра, наука, телеметрия, индикация — каждый в своём
файле. Файл миссии содержит только цифры цели и порядок шагов.

Всё проверено в полёте на сборке [«Оператор»](https://kerbal.ru/Operator),
KSP 1.12.5, kOS 1.6.0.1. Подробные разборы — в вики:
[библиотека модулей](https://kerbal.ru/Operator/wiki/kos-biblioteka.html) ·
[разбор ошибок вывода на орбиту](https://kerbal.ru/Operator/wiki/kos-vyvod-orbita.html) ·
[отладка и лимиты](https://kerbal.ru/Operator/wiki/kos-otladka.html) ·
[интерфейс и графика](https://kerbal.ru/Operator/wiki/kos-interfeys.html) ·
[управление по telnet](https://kerbal.ru/Operator/wiki/kos-telnet.html)

## Установка

Скопируй содержимое в архив kOS — это папка `Ships/Script/` в каталоге игры:

```bash
cp -r kos/lib kos/missions kos/check "<KSP>/Ships/Script/"
```

Проверь, что всё компилируется, прямо на стартовом столе:

```
RUNPATH("0:/check/libcheck.ks").
```

Полёт:

```
RUNPATH("0:/missions/dalnyak.ks").
```

> **Имена файлов только строчными.** На macOS и Linux kOS не найдёт файл,
> если регистр не совпадает. Поэтому папка называется `kos`, а не `kOS`.

## Что внутри

```
lib/          модули механики
missions/     файлы миссий: только цель и порядок
check/        прогон библиотеки без запуска двигателей
tools/        telnet-клиент для управления снаружи игры
```

### Шаблон миссии

`missions/_template.ks` — заготовка. Копируешь, меняешь пять чисел:

```kos
SET TGT_AP  TO 100000.   // целевой апоцентр, м
SET TGT_PE  TO 100000.   // целевой перицентр, м
SET TGT_INC TO 0.        // наклонение, °
SET TGT_LAN TO -1.       // долгота узла (-1 = не ждать окна)
SET PARK    TO 80000.    // опорная орбита, м
```

`missions/dalnyak.ks` — рабочий пример: спутник под контракт с заданной
долготой узла, со сбором науки на каждом рубеже.

## Правила, на которых всё держится

Они выведены из отказов, а не из теории — каждое стоило потерянной ракеты.

1. **Префиксы имён.** В kOS одно глобальное пространство имён. Каждый модуль
   помечает свои функции буквой: `u_`, `c_`, `s_`, `o_`, `a_`, `d_`, `t_`, `h_`.
2. **`GLOBAL FUNCTION`**, иначе функция не видна вызывающему файлу.
3. **Никаких побочных действий при загрузке.** Модуль только объявляет.
4. **Настройки — лексиконом**, обработчики — ссылками на функции через `@`.
   Модуль не должен знать ничего о конкретной миссии.
5. **Один владелец у объекта.** Раз `o_burn` снимает узел через `REMOVE`,
   он же его и вешает через `ADD`. Иначе `nd:DELTAV` падает с
   «Must attach node first» — и падает уже в полёте, компиляция это не ловит.
6. **Имена, занятые встроенными.** `r`, `v`, `q`, `alt`, `path`, `time`, `node`,
   `stage`, `config` и десятки других объявить нельзя. Проверяй прогоном
   `check/libcheck.ks` до пуска.

## Что уже отработало в полёте

- Подъём с ограничением угла атаки — аэродинамически неустойчивая ракета
  (оперение выше центра масс) выведена без единого срыва.
- Расписание тангажа вместо следования за потоком — экономия около 1500 м/с
  на скруглении орбиты.
- Автостейджер по отсутствию живых двигателей — переживает ступени-переходники,
  где двигателя нет вообще.
- Ожидание окна под долготу восходящего узла — модель, выведенная из
  телеметрии собственного полёта, попала в 311° с точностью 0,03°.
- Сбор науки на каждом рубеже с передачей только в вакууме: складная антенна
  раскрывается сама при передаче и ломается от напора в атмосфере.

## Управление снаружи игры

`tools/kos.py` — telnet-клиент к встроенному серверу kOS. Обычный `nc` не
годится: kOS требует RFC 1073 (размер окна) и RFC 1091 (тип терминала), а без
учёта уже согласованных опций стороны уходят в бесконечные переговоры.

```bash
python3 kos/tools/kos.py 'PRINT SHIP:APOAPSIS.'
python3 kos/tools/kos.py 'RUNPATH("0:/check/libcheck.ks").'
```

Включается в игре: панель kOS → TELNET, порт 5410 на `127.0.0.1`.

> Пока программа работает, в терминал писать нельзя — kOS воспримет ввод как
> прерывание и остановит её.

## Как участвовать

Библиотека открыта, и её есть куда растить. Что напрашивается:

- посадка на тело без атмосферы;
- стыковка;
- фазировка созвездия: развести N аппаратов по орбите равномерно;
- разворот плоскости и коррекция долготы узла уже на орбите;
- межпланетное окно и расчёт перелёта;
- пульт на виджетах kOS для ручных операций.

Правила простые: модуль в свой файл, префикс в именах, никаких побочных
действий при загрузке, проверка через `check/libcheck.ks` перед отправкой.
Присылай пулл-реквест или заводи
[issue](https://github.com/plagness/kerbal.ru/issues).

Если поймал грабли — опиши их в описании изменений. Половина ценности этой
библиотеки не в коде, а в списке того, обо что мы уже споткнулись.
